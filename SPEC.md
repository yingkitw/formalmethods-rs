# SPEC

Engine specification for `formalmethods`. Ported 1:1 from the TypeScript
engine in `../formalmethods` (`src/lib/formal/`).

## LTL grammar

Loosest to tightest binding; ASCII surface syntax only.

```
iff      := implies ("<->" implies)*
implies  := or ("->" implies)?           // right-associative
or       := and ("||" and)*
and      := until ("&&" until)*
until    := unary (("U" | "W" | "R" | "S") unary)*   // left-associative
unary    := ("!" | "X" | "G" | "F" | "Y" | "O" | "H") unary | atom
atom     := "(" iff ")" | "true" | "false" | IDENT
IDENT    := [A-Za-z_][A-Za-z0-9_]*
```

- Single `&` / `|` are accepted and mean `&&` / `||`.
- `X`, `G`, `F`, `U`, `W`, `R`, `Y`, `O`, `H`, `S`, `true`, `false` are
  reserved — they cannot be atom names. Only the *exact* operator tokens
  are reserved: `yes`, `Old`, `S2` still lex as atoms.
- `print_ltl` emits the same syntax; parse ∘ print round-trips exactly.
  Equal-precedence children get parens on the side the parser would
  re-associate away from: right children of `U`/`W`/`R`/`S`/`<->`/`||`/`&&`
  (left-associative chains), left children of `->` (right-associative).
- Past-time operators: `Y` (yesterday), `O` (once), `H` (historically),
  `p S q` (since).

## Formula JSON AST

`Formula` serializes as the TS engine's tagged union (`serde`), so ASTs can
cross process boundaries:

```json
{"kind": "atom", "name": "coin"}
{"kind": "not", "arg": <formula>}
{"kind": "until", "left": <formula>, "right": <formula>}
```

Kinds: `true`, `false`, `atom`, `not`, `and`, `or`, `implies`, `iff`,
`next`, `globally`, `finally`, `until`, `weak`, `release`, `yesterday`,
`once`, `historically`, `since`. `arg` for the unary kinds, `left`/`right`
for binary, `name` for `atom`.

## Semantics

### Finite traces — LTLf (`satisfies_trace`, `eval_at`)

Over `Trace = Vec<Set<atom>>` of length `n`, at position `i`:

| Formula | Holds iff |
| --- | --- |
| `X p` | `i+1 < n` and `p` at `i+1` (false at the last position) |
| `F p` | some `j ∈ [i, n)` has `p` |
| `G p` | every `j ∈ [i, n)` has `p` |
| `p U q` | some `j` has `q`, and `p` holds on all of `[i, j)` |
| `p W q` | `p U q` **or** `G p` |
| `p R q` | `¬(¬p U ¬q)` |
| `Y p` | `i > 0` and `p` at `i−1` (false at position 0 — never looks back past it) |
| `O p` | some `j ∈ [0, i]` has `p` |
| `H p` | every `j ∈ [0, i]` has `p` |
| `p S q` | some `j ≤ i` has `q`, and `p` holds on all of `(j, i]` |

The past is **unclamped**: at position `i` the past operators evaluate
positions `0..=i` regardless of `n`. On the empty trace position 0 still
evaluates — so `H p` is *false* there (the atom fails), unlike `G p`
which is vacuously true.

### Infinite runs — ultimately periodic (`satisfies_periodic`, `eval_periodic_at`)

`PeriodicTrace { prefix, cycle }` = `prefix` then `cycle` forever. Past the
prefix, atoms repeat with period `L`, so F/G/U are decided by scanning one
full period: `end = max(i, |prefix|) + L`. `X` wraps around the cycle. An
empty `cycle` falls back to LTLf on the prefix. Past operators evaluate
positions `0..=i` on the unrolled run, so inside the loop they see earlier
iterations of the cycle as the past.

## Kripke structures

```json
{ "atoms": ["ready", "coin"], "initial": ["idle"],
  "states": [{ "id": "idle", "atoms": ["ready"], "next": ["paid"] }] }
```

`parse_kripke(&Value)` validates: non-empty `states`, unique ids, every
`initial`/`next` id exists. Undeclared atoms used by a state are added with
a **warning**. Empty `initial` warns — every property holds vacuously.
`validate_kripke` applies the same rules to programmatically built specs.

## Model checking (`model_check`)

Enumerates every **simple path** from every initial state up to `depth`
(default `|states|`), and for each path every **lasso**: back-edges into
the current path close a cycle; a dead end closes a self-loop (the system
stutters forever). Each lasso is evaluated under periodic semantics.

Options: `depth`, `path_budget` (default 20 000), `max_counterexamples`
(default 3).

### Verdict honesty (product invariant)

| Verdict | Meaning |
| --- | --- |
| `violated` | ≥1 lasso falsifies the formula — always genuine |
| `holds` | enumeration was exhaustive: `depth ≥ |states|` **and** budget not hit |
| `incomplete` | bounded search found nothing — *unknown*, said out loud |

No code path may report `holds` unless the enumeration was exhaustive.

## Falsification (`falsify`)

Random traces of `length` positions (default 6, max 64), each atom
independently present with p=½, up to `iterations` tries (default 300, max
100 000), PRNG = mulberry32 (same algorithm as the TS engine). First
violating trace is shrunk by delta-debugging: drop positions, then drop
individual atoms, while the trace still violates. `violated: false` means
*not falsified*, never *proven*.

`guided: true` switches to coverage-guided mode: a corpus keeps every
trace that introduced an unseen state signature (atoms sorted,
comma-joined), and half the campaign is generated by mutating corpus
entries — drop a position, duplicate one, or toggle an atom. Novelty
seeking over the 2^|atoms| space; the result reports `coverage`
(`states_seen`, `states_possible`, `corpus_size`, corpus capped at 128).

`shrink_trace_for(&trace, &formula)` is the formula-aware variant:
atoms the formula never mentions are unobservable, so they're stripped
unconditionally before delta-debugging — the same violation, strictly
more readable. `falsify` itself stays semantics-blind (TS parity);
compose it on the returned counterexample.

`gen_formula(&atoms, max_depth, &mut rng)` generates random formulas
(randltl-style, depth-bounded, whole grammar including past-time
operators) — for round-trip fuzzing and conjuring random properties
to probe a spec with.

## Runtime monitoring (`Monitor`)

`Monitor::new(&formula)` then `feed(&state)` consumes a stream one state at
a time; `verdict()` reports `Satisfied` / `Violated` the moment the outcome
is inevitable (residual reduced to `true`/`false`), else `Pending`.
`close()` ends the stream and returns the final `bool`.

Implementation: Bauer-style formula progression — `feed` rewrites the
formula into the residual obligation for the remaining suffix
(`P(G f, s) = P(f, s) && G f`, etc.); `close` evaluates the residual on the
empty suffix under LTLf. Past operators resolve against the consumed
prefix kept as history. `Monitor::close` agrees with `satisfies_trace` on
the consumed log — same property, two execution modes (asserted by tests).

`monitor_trace(&formula, &trace)` runs the batch form: one
`MonitorStep` per consumed state — `{position, atoms, residual, status}`
with status `met` / `broken` / `owed` (the wire names the TS engine uses;
`Satisfied`/`Violated`/`Pending` in Rust). `monitor_ltl` exposes it.

## CTL grammar (`parse_ctl`)

Branching-time sibling of the LTL grammar; same connectives and binding
order, path quantifiers replace the temporal layer.

```
iff     := implies ("<->" implies)*
implies := or ("->" implies)?
or      := and ("||" and)*
and     := quant ("&&" quant)*
quant   := ("E" | "A") "[" iff "U" iff "]" | unary
unary   := ("!" | "EX" | "AX" | "EF" | "AF" | "EG" | "AG") unary | atom
atom    := "(" iff ")" | "true" | "false" | IDENT
```

- `E`, `A`, `U`, `EX`, `AX`, `EF`, `AF`, `EG`, `AG` are reserved.
- `ctl_check` computes exact satisfaction sets by fixpoint labelling
  (`EU`/`AU` least fixpoint, `EG` greatest). Verdict is `holds` iff every
  initial state satisfies; CTL checking is always exact, so `incomplete`
  never appears.
- Dead ends stutter here too: a state with no out-edges has an implicit
  self-loop, so `AX φ` at a dead end ≡ `φ` — never vacuous.

## Coverage (`analyze_coverage`)

Given a model and test traces (state-id sequences), reports covered /
missing states and transitions (`from -> to`), percentages, and state ids
appearing in traces but not the model (`unknown_states`). Edges the traces
took that the model does not declare are `unknown_transitions` —
impossible moves, surfaced not dropped. Coverage is a negative metric: it
proves absence of testing, never presence of correctness.

## Mutation coverage (`mutate`)

Two directions of "is the spec actually tested?", both exhaustively
re-checked:

- **Model mutants** — `mutants(&model)` enumerates single-point faults
  (`Unlabel`, `Relabel`, `Detransition`); `mutation_report(&model,
  &formulas)` re-runs the formula suite on each: `killed` / `survived` /
  `survived_incomplete` (a surviving mutant is only proven under
  exhaustive check) / `invalid`, plus a kill rate over valid mutants.
- **Formula mutants** — `spec_mutants(&formula)` wraps each node position
  in `!`; `operator_mutants` applies only strictly-stronger or
  incomparable transforms (`F→G`, `W→U`, `∨→∧`, `∨→operand`, `O→H`,
  `X→arg`) — never an entailed weakening, which could only survive.
  `analyze_spec_coverage(&formula, &model, &opts, max_mutants)` (default
  cap 64, smallest target first) re-checks each mutant: `killed` (with
  witness lasso) / `survived` / `unknown`, plus a mutation score —
  `killed/total` percent, `None` unless the base verdict is `holds`.

## Depth sweeps (`analyze_depth`)

Re-runs `model_check` at every prefix depth `1..=|states|` with the same
budget. Rows carry `depth`, `verdict`, `complete`, `checked_lassos`; the
sweep reports `first_violation_at` (monotone — once violated, never
recedes) and `conclusive`, the exhaustive last row. Below `|S|`,
`incomplete` is an honest unknown; at `|S|` the verdict is the answer.

## Counterexample replay (`replay`)

`counterexample_run(&model, &ce)` rebuilds the `PeriodicTrace` a lasso
came from. `falsifying_window(&formula, &run, &reps)` (default reps
`[2,3,4,6,8]`) unrolls prefix + whole loops until the finite trace still
fails under LTLf — a pasteable regression test. `None` means the
violation witnesses infinity itself (e.g. `F G p` on a flicker) and is
not finitely replayable. `fm model_check` emits `replay` per
counterexample.

## CLI (`fm`)

`fm <tool> '<json-args>'` → JSON result on stdout, exit non-zero on error.
Pass `-` as the args to read the JSON object from stdin (pipe-friendly).
Tools: `check_ltl`, `monitor_ltl`, `model_check`, `ctl_check`,
`analyze_depth`, `mutation_report`, `analyze_spec_coverage`,
`falsify_property`, `analyze_coverage`, `explain_concept`,
`read_skills_guide` — argument shapes mirror the sibling project's MCP
tools. `read_skills_guide` takes no args and returns `{path, source,
content}` — `SKILLS.md` verbatim via `include_str!`, so the served guide
is never stale. `ctl_check` takes
`formula` in CTL syntax plus `model`, and reports `satisfying` /
`violating_initials`; `mutation_report` takes `model` plus `formulas`
(an array of LTL strings) and reports the mutant tally and kill rate;
`falsify_property` accepts `guided: true` for coverage-guided generation;
`model_check` counterexamples carry `prefix`/`cycle`/`replay`/`truth_table`.
